# 小芽日常 · 婴幼儿日常照护小程序

按月龄给出「吃 / 动 / 学 / 睡」建议，按**小区级位置**取天气算出今天该穿什么，再一键推给一起带娃的人。

---

## 一、功能

| 模块 | 说明 |
|---|---|
| 宝宝档案 | 小名、性别、出生日期、体重、身高、备注；支持多宝宝切换，全部存本机 |
| 月龄建议 | 0–36 月分 8 个档（0-1 / 2-3 / 4-5 / 6-8 / 9-11 / 12-17 / 18-23 / 24-36），每档含吃、动、学、睡四段 + 注意事项，可左右切换查看前后月龄 |
| 地点（北京市 → 区 → 小区） | 三级精确到小区；支持常用地点（家 / 奶奶家）一键切换；山区自动计入温差 |
| 天气穿衣 | 按地点坐标取 Open-Meteo（免密钥）：气温、体感、风力、湿度、紫外线、降水概率、最高最低温 → **温度 × 月龄双维**规则引擎，输出该月龄的具体款式（内层/外层/头部）+ 睡袋温度对照表 + 情境提醒 |
| 疫苗护理 | 记录疫苗类型、剂次、接种日期；按疫苗类型和「接种后经过多久」给出分阶段注意事项（留观 / 当天 / 1-3 天 / 3-14 天）+ 可能出现的反应 + 就医警示 + 下一针；接种记录只展示近 3 次、可展开全部；选未来日期则进「待安排疫苗」列表，到期自动转为接种记录；打了五联会自动覆盖百白破与脊灰，也可手动移除某一针；内置清单没有的自费疫苗可以自己加 |
| 推送给指定人 | 生成一张 1280px 宽的「今日卡片」（含地点），可转发微信好友/群、保存相册、复制文字版；家人名单支持勾选推送对象 |
| 每日提醒（可选） | 走微信订阅消息，需自行申请模板 ID |

## 二、地点精度：北京市 → 区 → 小区

### 数据模型

```js
place = {
  city: '北京市',
  district: '朝阳区',
  community: '望京西园',
  address: '北京市朝阳区望京街道望京西园四区',  // 地图返回的原始地址
  lat: 39.9963, lon: 116.4715,
  source: 'poi' | 'map' | 'district' | 'manual'
}
```

- `settings.place` 是当前生效地点，`settings.places` 是常用地点列表，`settings.activePlaceId` 指向当前那一项。
- 旧版本只存了 `city / lat / lon` 的，`getSettings()` 里会自动迁移成上面的结构（`utils/place.js` 的 `migrateLegacy`）。

### 小区是怎么拿到的（四条路，按可用性自动降级）

| 路径 | 依赖 | 拿到什么 | 何时用 |
|---|---|---|---|
| ① `place` 云函数搜 POI | 腾讯位置服务 WebService Key | 小区名 + 区 + 精确坐标 | 配了 key 时最顺，输入「望京西园」直接出候选 |
| ② `wx.choosePoi` | 微信「位置接口」权限 | 小区名 + 地址 + 坐标 | 没 key 时的首选，微信内置 POI 搜索器 |
| ③ `wx.chooseLocation` | 微信「位置接口」权限 | 坐标 + 附近地址 | ②不可用时的地图选点 |
| ④ 手填小区名 | 无 | 小区名 + **区中心坐标** | 永远可用，保证功能不阻塞 |

关键取舍：**区级一定可用**（内置北京 16 区中心坐标），小区级是「锦上添花」。没有地图 key、没有位置权限，用户依然能完成设置并拿到天气，不会卡在授权页。

### 配腾讯位置 Key（可选，但推荐）

1. 腾讯位置服务控制台 → 应用管理 → 创建 Key → 勾选「WebServiceAPI」
2. 云开发控制台 → 云函数 → `place` → 配置 → 环境变量：`TMAP_KEY = 你的key`
3. 重新部署 `place` 云函数

配好后额外解锁两件事：输入即搜的小区候选列表、以及「用当前位置」时自动反查区县和小区名（逆地理编码）。

### 山区修正

门头沟、房山、怀柔、平谷、密云、延庆六个区含较大海拔落差，`utils/place.js` 里标了 `mountain: true`。命中后：

- 温度先扣 2℃ 再匹配穿衣档（`clothing.recommend` 的 `mountain` / `mountainOffset` 参数）
- 依据行会写明「按体感 19℃，山区 -2℃，10 月龄 -2℃ 修正为 15℃」
- 注意事项里追加一条山区温差提示

> 注意：穿衣档宽约 3℃，所以 2℃ 的修正不保证一定跨档。文案写的是「已把这段温差算进去」而不是「已降一档」，避免说了没做到。

### 天气真的会不一样吗

Open-Meteo 的网格分辨率约 1–11 km，**同城区内不同小区差别很小**，小区级的主要价值是：① 山区/城郊交界处差异真实存在；② 卡片和推送里能明确写出「朝阳区·望京西园」，长辈一眼知道是给哪个孩子的。这点在 README 里说实话，比夸大精度更有用。

## 三、穿衣引擎：温度 × 月龄

穿衣不是按温度查一句「多穿点」，而是**两个维度交叉**：温度档（9 档）× 月龄阶段（5 段）。

### 为什么加月龄维度

只用温度，会给出「长袖薄棉连体衣 + 开衫」这种放之四海皆可、但不像婴儿装的答案。8 个月的宝宝在 22℃ 该穿**春秋连体衣**，16℃ 该穿**夹棉连体衣**——同一个温度下，2 个月和 30 个月的衣服根本不是一类东西：

| 修正后温度 | 2 月龄（新生儿） | 8 月龄（爬行期） | 30 月龄（幼儿期） |
|---|---|---|---|
| 18℃ | 夹棉和尚服 + 夹棉抱被 | 春秋连体衣（毛圈）+ 薄夹棉马甲 | 长袖 T 恤 + 卫衣 + 长裤 |
| 12℃ | 薄棉内衣 + 夹棉和尚服 | 夹棉连体衣 + 夹棉外出服 | 加绒卫衣 + 加绒长裤 + 夹棉外套 |

### 匹配流程

1. 取**体感温度**（不是气温）
2. 月龄温度修正：<3 月 −3℃、3–12 月 −2℃、12–24 月 0、≥24 月 +1℃
3. 山区再 −2℃（门头沟 / 房山 / 怀柔 / 平谷 / 密云 / 延庆）
4. 落入 9 个温度档之一（极冷 / 严寒 / 较冷 / 冷 / 凉 / 微凉 / 舒适 / 偏热 / 炎热）
5. 用「温度档 × 月龄阶段」查出**该月龄的具体款式**，输出内层 / 外层 / 头部三层
6. 叠加情境提醒：温差 ≥8℃、风力 ≥6 级、雨雪、紫外线 ≥6、闷热高湿、极寒、≥32℃、6 月龄内捂热风险

月龄阶段与款式取向：

| 阶段 | 月龄 | 主打款式 | 注意 |
|---|---|---|---|
| 新生儿 | 0-2 | 和尚服、包屁衣、抱被 | 前开襟，换尿布不折腾脖子 |
| 小婴儿 | 3-5 | 一体式连体衣 | 还不会独坐，护住肚子 |
| 爬行期 | 6-11 | 春秋连体衣、夹棉连体衣、分腿款 | 爬得多易出汗，别穿长袍 |
| 学步期 | 12-23 | 分体：卫衣 + 长裤 | 裤腰别太紧，留纸尿裤空间 |
| 幼儿期 | 24-36 | 好穿脱的分体 | 活动量大，宁可少一件 |

### 睡袋：给一整张区间表，而不是一个数

只给一个 TOG，家长遇到「明晚降温 5 度」还得再问一次。所以睡袋改成**表格 + 当前档高亮**，7 个室温区间全部列出：

| 室温 | 睡袋 | 穿盖 |
|---|---|---|
| ≥28℃ | 0.2-0.5 TOG | 无袖睡袋，或只穿短袖包屁衣 |
| 26-27℃ | 0.5 TOG | 短袖包屁衣 + 0.5 TOG 睡袋 |
| 24-25℃ | 1.0 TOG | 短袖 / 薄长袖连体衣 + 1.0 TOG 睡袋 |
| 21-23℃ | 1.5 TOG | 长袖连体衣 + 1.5 TOG 睡袋 |
| 18-20℃ | 2.5 TOG | 长袖连体衣 + 2.5 TOG 睡袋 |
| 15-17℃ | 3.0 TOG | 加厚长袖连体衣 + 3.0 TOG 睡袋 |
| ＜15℃ | 3.5 TOG | 3.5 TOG 睡袋 + 长袖保暖内衣 |

- 当前室温那一行会高亮并标「当前」，其余行当参考表用。
- 睡袋**款式也按月龄给**：0-5 月一体式 / 襁褓（会翻身即停用襁褓），6 月龄以上分腿睡袋。
- 室温由室外体感**分段估算**：≤8℃ → 21℃（供暖季，室温被暖气锚住）、8–23℃ → 线性过渡到 23℃（停暖 / 开窗）、>23℃ → 继续上浮；结果夹在 10–33℃。
- 卡片上有 **室温 −/＋ 步进器**：家里有温度计就按实测改，整张表会重算并重新高亮，改动后标「手动」，可一键「恢复估算」。

> **两个坑都是写测试时才发现的。**
> 一是室内温度**不参与月龄修正**——房间冷不冷跟宝宝几个月大没关系，否则同一天气下两个孩子的室温会算得不一样。
> 二是最早的估算是「室外 + 4℃」，室外 −5℃ 会算出室内 −1℃，于是推荐 3.5 TOG。暖气房里捂到 3.5 TOG 是实打实的捂热风险（婴儿过热与 SIDS 相关），所以改成供暖锚定：室外 −5℃ 稳定落在 21℃ → 1.5 TOG。

## 四、疫苗护理：记录一针，给一段时间的注意事项

打针本身只要几分钟，麻烦的是之后三天：该不该测体温、针眼化脓了要不要挤、什么时候出现反应算正常。所以这一块不是「疫苗清单」，而是**按接种后的时间推进的护理脚本**。

### 记一条要填什么

疫苗（18 种：10 种一类免费 + 8 种二类自费）、第几剂、**接种日期**、门诊、备注。

页面上没有「具体时间」这个输入框——家长手里只有接种证上那个日期，追问几点几分只是给自己添麻烦。引擎内部统一按当天 09:00 计（门诊基本上午开诊），「留观 30 分钟」「接种后 24 小时」这些节点仍然成立。

### 记录两种命运：已发生的进记录，未来的进「待安排」

保存时如果日期**晚于今天**，这条记录不会混进接种记录里，而是进「待安排疫苗」列表——因为它还没发生：

| | 接种记录 | 待安排疫苗 |
|---|---|---|
| 触发条件 | 日期 ≤ 今天 | 日期 > 今天 |
| 参与护理提醒 | 是 | 否（没打就没有反应可护理） |
| 计入「已接种 N 针」统计 | 是 | 否 |
| 把免疫规划表对应行标成已接种 | 是 | 否（那行仍然是「快到了」或「该打了」） |
| 排序 | 由近到远（最近的在最上面） | 由近到远（最近要打的在最上面） |

「待安排」每行显示「日期 / 疫苗名 · 第 N 剂 / 还有几天 + 门诊」，点进去可以改日期或删掉。等日期过去了，这条记录自动出现在接种记录里，并开始按阶段推送护理事项——不需要手动搬。

这样做的理由很实在：把「约好下周三去打」和「上周三已经打完」混在一张列表里，会让护理引擎对着一针还没打的疫苗喊「今天可能低热」。

### 接种记录只展示近 3 次

记录攒起来以后一屏铺不完，所以默认只留最近 3 次，标题栏右侧显示「展示全部 N 次」，点开展开全量、再点收起。卡片底部同时给一句「共 N 次 · 免费 X · 自费 Y」，不用展开也知道总共打了多少。

### 护理分成 5 个阶段

| 阶段 | 时间窗 | 核心任务 |
|---|---|---|
| 留观中 | 0–30 分钟 | 不许提前走；看脸色、呼吸、有没有出冷汗 |
| 接种当天 | 0.5–24 小时 | 每 4 小时测体温；针眼不揉、不泡澡；多喂一次奶 |
| 1–3 天 | 24–72 小时 | 早晚各测一次体温；红肿硬结别热敷；辅食清淡 |
| 3–14 天 | 72–336 小时 | 盯减毒活疫苗的**迟发**反应；卡介苗的卡疤进程 |
| 观察期已过 | >14 天 | 正常照护，去看下一针什么时候 |

### 同一阶段，不同疫苗给的话不一样

这是这个模块最关键的部分——通用护理模板是不够用的：

| 疫苗 | 特异性提示（覆盖通用模板之上） |
|---|---|
| 卡介苗 | 2–3 周局部红肿→化脓→结痂是**正常过程**，别挤别涂药别包扎；3 个月没卡疤要复查 |
| 麻腮风 / 乙脑 / 水痘 | 反应常在第 5–12 天（水痘 2–3 周）才出现，那时打针已经过去很久，家长容易想不到 |
| 脊灰（口服） | 服苗前后 30 分钟不吃热食、不喝热水；免疫缺陷改用 IPV |
| 轮状（口服） | 疫苗病毒随大便排出，换尿布后洗手；阵发性哭闹 + 呕吐 + 果酱样便要急诊（肠套叠） |
| 百白破 / 五联 / 13 价肺炎 | 反应比别的针明显，4–6 小时后开始低热，48 小时内多能退 |
| 乙肝 | 第 1 剂必须在出生 24 小时内；母亲 HBsAg 阳性要同时打免疫球蛋白 |
| 流感 | 6 月龄以下不能打，靠家里人接种形成保护圈 |

反应还按时间窗分成两类展示：
- **此时可能出现**（当前已进入该反应的时间窗）
- **接下来可能出现**（带「5 天后」这种倒计时）——麻腮风打完第 2 天，页面就会预告「5 天后可能低热、出疹」，免得家长以为是别的原因。

### 记录之外：对照免疫规划表

`data/vaccines.js` 里的 `PLAN` 是 22 行的一类疫苗接种程序（出生 → 6 岁）。拿宝宝月龄和已记录剂次一比，得出四种状态：

`已接种` / `该打了` / `已过建议月龄`（超过 2 个月没记录）/ `快到了`（1 个月内）

这张表收在页面底部的折叠区里，不占首页版面——它是一张「查阅型」的表，家长想核对时才展开，而不是每天弹一个卡片催打针。早先版本在顶部放过一张「按免疫规划表，这些该安排了」的摘要卡，和上面「待安排疫苗」的语义打架（一个是你自己约好的，一个是程序表推算的），所以删掉了，只保留这一处可折叠的全表。

- 一针都没记过时，表标题不会写「该打乙肝了」（对一个 8 月龄宝宝没意义），而是「还有 13 针没记录」，并把**当前月龄刚到期**的那几针排在前面。
- 二类疫苗不进这张表——自费疫苗按家庭和门诊建议自行选择，不替家长做决定。

### 打联合疫苗后，被覆盖的单苗自动让位

五联打完，规划表里的百白破和脊灰就不该再催——所以引擎里有一张替代关系表（`COVER_RULES`）：

| 打了 | 覆盖规划表里的 |
|---|---|
| 五联疫苗 | 百白破 1–4 剂、脊灰 1–3 剂（**脊灰第 4 剂在 4 岁，五联不含，仍单独提醒**） |
| 甲肝灭活 | 甲肝减毒活（二者二选一） |

覆盖是**按剂次逐条推导**的：只打了 1 剂五联，就只覆盖百白破第 1 剂和脊灰第 1 剂，不会一口气把 4 针都划掉。被覆盖的行显示成「已覆盖」，点一下会说明是哪一针覆盖的、想取消就删那条记录。

### 也能手动移除某一针

不是所有情况都能靠规则推导：外地打过了没带回来、医生建议暂缓、孩子有禁忌症……所以每一行都可以点开选择：

- **标记为已接种** → 跳到记录页并预选好疫苗和剂次
- **不再提醒这一针** → 从表里移走，收进底部「已移除 N 项」，随时可以恢复

状态优先级：`已接种` > `已覆盖` > `已移除` > 按时间推导的四种。移走的东西不会真的消失，避免「点错了找不回来」。

### 内置清单没有的疫苗，自己加

二类疫苗的厂家和品种太杂（各地门诊供应的手足口、轮状、13 价程序都不一样），硬编码清单一定会漏。所以记录页的二类分类末尾有个「＋ 自定义」：

- 填名称、剂次数（1–6）、备注，保存后立刻可以记录接种
- 自定义疫苗**没有专属护理知识库**，护理页只给通用事项，并明确写一句「这是你自己添加的疫苗，按通用事项护理，具体看说明书」——不假装懂
- 它不进免疫规划表（自费苗不替你安排时间），删除时会提示会连带清掉多少条记录

## 五、跑起来（3 步）

1. **导入项目**
   微信开发者工具 → 导入项目 → 选择本目录 `xiaoya-daily`。
   `project.config.json` 里 AppID 是 `touristappid`（游客模式，可直接打开预览）。

2. **看首页**
   首次进入会引导添加宝宝（只需小名 + 出生日期），保存后首页立刻出现今日建议。

3. **设置地点**
   进「天气穿衣」页 → 点顶部地点条 → 选到区 → 选/搜/填小区 → 「用这个地点」。

### 关于天气的两条路径

| 路径 | 何时用 | 要不要额外配置 |
|---|---|---|
| 客户端直连 Open-Meteo | 本地开发、快速验证 | 已设 `urlCheck: false`（等价于「不校验合法域名」）。**正式版/真机需要把 `api.open-meteo.com` 加入 request 合法域名** |
| `weather` 云函数代理 | 正式上线推荐 | 开通云开发 → 环境 ID 填进 `app.js` → 部署 `weather` 云函数。不受域名白名单限制 |

前端是三级降级：**云函数 → 直连 → 30 分钟本地缓存**（缓存按坐标 3 位小数分桶，不同小区各自缓存），任一环挂掉都不白屏。

## 七、推送怎么做

微信不允许小程序随意给「特定的人」推送，所以做了两条路，第一条**现在就能用**：

### 路径 A：卡片转发（零配置，立刻可用）

首页 →「生成今日卡片」→ 选「发给谁」→ 卡片上出现「给 妈妈、奶奶 看看」和「朝阳区·望京西园」→
- `转发给微信好友`：直接发给某个人或家庭群
- `保存图片到相册`：发朋友圈或群里发原图
- `复制文字`：纯文本长辈也看得清

### 路径 B：订阅消息每日提醒（需申请模板）

1. 公众平台 → 订阅消息 → 选用「一次性订阅」模板
2. 模板 ID 填进 `app.js` 的 `globalData.tmplIds`
3. 部署 `pushTip` 云函数（自动建 `xyd_push_subscriptions` 集合）
4. 「带娃人」页 → 开启每日提醒 → 授权

⚠️ 微信硬限制：**一次授权只能下发一条**。想每天收到，要么每天引导授权，要么改用服务号模板消息。

## 十、合规提示

## 十一、已知限制

- 建议是年龄段通用参考，不针对早产、过敏、疾病等情况做个体化调整。
- 内置行政区划只有北京市 16 区。要扩到其他城市，在 `data/districts.js` 里加区县数组即可，其余逻辑不用动。
- 小区 POI 检索依赖腾讯位置服务 Key；没有 key 时只能用微信地图选点或手填。
- Open-Meteo 为境外服务，国内访问偶有波动；正式上线建议换和风/高德，只需改 `cloudfunctions/weather/index.js` 一个文件。
- 订阅消息一次授权一条，做不到「一次授权、长期自动推送」。
- 疫苗护理的文案是通用科普（依据国家免疫规划程序和疫苗说明书常见反应描述），**不能替代接种门诊的个体化告知**；早产、免疫缺陷、过敏体质、正在用激素或免疫球蛋白的宝宝，接种与护理一律听医生。
- 疫苗库覆盖 18 种常见疫苗，程序表只排一类疫苗；各地二类疫苗的厂家程序（如 13 价肺炎 2/4/6/12 或 3/4/5/12）有差异，以门诊方案为准。
- 自定义疫苗只是「记一笔」，没有专属护理知识，也不会进免疫规划表；替代关系表只写了五联→百白破/脊灰、甲肝灭活→甲肝减毒活这两组明确可替代的，其余联合疫苗（如四联、AC-Hib）需要自己在规划表里点「不再提醒」。
- 接种记录只存本机，没有云端同步；换手机或清缓存会丢，重要记录建议同时留在预防接种证上。
- 「待安排 → 接种记录」的搬家是在**打开页面时按当天日期现算**的，没有后台定时任务：约好的那天如果没打开小程序，护理提醒不会自己开始推送，第二天打开才会看到。
